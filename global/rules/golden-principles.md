# Golden Principles

- 코드 변경은 요청된 범위만 (Surgical Changes): 요청된 줄만 변경, 인접 코드 "개선" 금지, 미사용 import 등 자기 변경이 만든 것만 정리
- DRY, KISS, YAGNI 원칙
- 함수 50줄 이내, 파일 800줄 이내, 네스팅 4단계 이내
- Immutability 우선 (const, readonly, Object.freeze)
- 경계에서 입력 검증 (zod, Pydantic)
- 결론 먼저, 근거는 그 다음
- 불확실하면 가정을 밝히고 질문
- TDD: RED → GREEN → IMPROVE, 80%+ 커버리지
- Context 75% Rule: 75% 초과 시 새 세션으로 분리
- 복잡한 변경은 계획 먼저 (권고 — 강제 게이트 아님): 파일 수가 아니라 *불확실성*이 기준이다.
  변경 범위가 이미 명확하면 파일 3개든 10개든 바로 진행한다.
  (2026-08-09: 파일 수 기준 HARD-GATE 폐지. 훅 `hardGateGuard.js` 가 `.claude/plans/` 에
   `.md` 하나만 있으면 영구 통과하는 구조라 2026-05-09 이후 무발화였고,
   문서만 남기면 "있는 줄 알았는데 꺼져 있던 게이트"가 재발한다 — 훅과 원칙을 함께 제거)
- Evidence-Based Completion: 실행 증거 없이 완료 선언 금지

## Anti-Rationalization

| 원칙 | 변명 | 현실 |
|------|------|------|
| TDD | "테스트 필요 없을 정도로 간단" | 간단한 코드도 깨진다. 30초면 된다 |
| TDD | "나중에 추가할게요" | 나중에 쓴 테스트는 happy path만 커버 |
| Immutability | "성능상 mutation 필요" | 프로파일링으로 증명한 뒤에만 |
| 파일 크기 | "아직 괜찮아요" | 400줄 넘으면 분리 검토 |
| 계획 | "범위 파악은 하면서 하지 뭐" | 무엇을 바꿀지 모른 채 시작하면 되돌리기가 더 비싸다 |
| 게이트 | "훅이 막아줄 거야" | 훅은 조용히 꺼진다. 발화 여부를 실측하지 않은 게이트는 없는 것과 같다 |
| Evidence | "이미 잘 되고 있어요" | 증거 없는 주장은 거짓. 실행 결과를 보여라 |
| Surgical | "이왕 하는 김에 정리도..." | 요청된 줄만 변경. 정리는 별도 요청 |
